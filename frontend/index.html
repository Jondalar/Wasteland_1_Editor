    Portrait editor

    Up to 4 ANIMATIONS run concurrently (blink / mouth / glint). Each is a looping sequence of full states: paint every frame as WHAT IT SHOWS, set how long it stays (delay, game walks). A frame left = base is a pause; the loop returns to the base automatically. The EOR masks are computed from your frames at save. 44×84 MC-pixels, FIXED 4 colours (black / red / blue / white).
    Drop a PNG onto a FRAME to load it into that one — that is how you upload a whole animation, frame by frame. Dropped elsewhere (or via ⇪ PNG) it goes into the frame you are currently editing; the highlighted card shows where it will land. Replacing the base re-bases the tracks: pixels that were not animating follow the new picture, the animated ones keep their state. It lands in the editor first, so nothing is written until you press Save. A portrait stores no colour of its own, so the image may use at most those four colours; more is refused, and near matches are snapped and reported.

    What this is

    The party a NEW GAME starts with: 8 records of 256 bytes, the $F400–$FBFF window. Record 0 is the header, 1–4 are the rangers, 5–7 spare. The cart picks a blob at build time (WL_PARTY); edits go to editor/work/save/ and baseline/save/ stays pristine.

    Only the fields you change are written — the rest of each 256-byte record stays byte-identical, including the parts nobody has identified yet.

    Blueprints the three kinds of re-usable thing: patterns (shapes the game repeats), services (shop, doctor, library, talker) and buildings (a map region with its cells, scripts, texts, tiles and foes). Always copied into the quest that uses one.
